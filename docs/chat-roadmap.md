# 게임 안 채팅 로드맵

상태: 초안(2026-11-19). 구현 세부는 [in-game-chat.md](in-game-chat.md)에 있다. 이 문서는 무엇을 어떤 순서로 만들지 정한다.

## 전제

- 플레이 환경은 두 가지다. 외부 채팅(사용자가 게임 화면을 안 볼 수도 있다)과 게임 안 채팅창(사용자가 게임 화면을 같이 본다). MCP는 비슷하게 쓰지만 UX는 따로 설계한다.
- 지금은 게임 안 채팅창에 집중한다. 외부 채팅이 쓰는 MCP 도구(`state`, `act`, `info`, `search`, `render_*`, `screenshot`)의 동작은 깨지지 않게 한다. 새 기능은 추가로만 넣고, 게임 안 채팅에만 필요한 도구는 외부에 보이지 않게 따로 둔다.
- 플레이 단계는 네 가지다: 코멘터리(에이전트가 가볍게 한마디), 코플레이 Low(사용자 주도, 에이전트가 근거 수집), 코플레이 High(에이전트 주도, 중요한 선택만 사용자 승인), 오토플레이(에이전트가 런을 진행).
- 세션은 메인 메뉴의 관제 세션 하나와, 런마다 새로 여는 플레이 세션으로 나눈다. 한 세션에서 여러 런을 하면 컴팩트가 반복되며 판단력이 떨어졌다.
- 모델은 당분간 Sonnet, effort medium으로 고정한다.
- 사용자의 평소 Claude Code 설정(CLAUDE.md, 스킬, 설정, 환경변수)이 채팅에 섞이지 않게 한다.

### 만든 구조

- 파일(게임 전용 폴더 `%LOCALAPPDATA%\sts2-agent-mcp`): `sessions.json`(관제 세션 ID, 런별 플레이 세션 ID와 종료 여부, 다음 런 브리핑, 관제에 넘길 지난 런 보고), `notes.md`(학습 메모), `reports/`(런 보고), `prompts/`(같은 이름의 파일이 있으면 기본 프롬프트 조각을 대신한다. `prefs.md`는 플레이어가 원하는 것으로 덧붙는다).
- 런 구분: 런 시드. 같은 시드라도 끝난 런이면 새 세션을 연다.
- 프롬프트: `common` + `ingame` + 역할(`role-control` / `role-play`) + 플레이 단계(`level-*`, 플레이만) + `prefs`. 시스템 프롬프트는 대화에 저장되지 않고 실행할 때마다 넘기므로, 재개한 대화도 지금 프롬프트로 돈다. 플레이 단계를 바꾸면 플레이 세션 프로세스를 다시 띄워 새 프롬프트를 읽게 하고 `[설정]` 알림을 붙인다.
- 플레이 세션의 첫 메시지 앞: `[런 브리핑]`(단계, 관제가 남긴 브리핑, 학습 메모). 이후 메시지마다 `[게임 기록]`(이벤트 기록 최대 40줄, 플레이어가 열어 본 화면).
- 게임 오버 화면: 플레이 세션에 `[런 종료]` 보고를 요청하고, 답을 `reports/`에 저장하고, 관제 세션의 다음 메시지 앞에 `[지난 런 보고]`로 붙인다.
- 자동 반응: 코멘터리는 전투 끝·방 도착·덱 변화, 코플레이 Low는 여기에 전투 시작·턴 시작(2턴부터). 세션이 쉬고 있고 플레이어가 입력 중이 아닐 때 6초 이상 간격으로 모아서 보낸다. 코플레이 High와 오토는 대신 "계속" 루프: 답에 선택지가 없으면 1.5초 뒤 `[자동] 계속`. "멈춰/그만/잠깐"이면 멈추고 "계속/진행"이면 다시 간다. 런마다 최대 400번.
- 전용 도구: `show_cards`, `show_relics`, `open_view`(덱/더미/지도/카드·유물 상세), `map_route`(실제 지도 위 경로), `notes`, `play_level`, `run_brief`.
- 카드 표시: 게임의 카드 노드를 화면 밖 뷰포트에서 그려 그림으로 넣는다. 툴팁은 채팅창 안에 직접 그린다(카드 설명, 강화 후 설명, 게임의 키워드 툴팁 내용). 유물은 아이콘과 같은 방식의 툴팁.

### 시험할 것

- 런 시작·이어하기·게임 오버·메인 메뉴 복귀에서 세션 전환과 대화 기록 다시 그리기.
- 게임을 다시 켠 뒤 관제 세션과 진행 중 런의 플레이 세션 재개.
- 자동 반응 빈도(너무 잦지 않은지), 계속 루프가 선택지에서 멈추는지.
- 카드 그림(뷰포트 렌더가 채팅창 크기에서 선명한지), 툴팁 위치.
- `open_view`가 전투 중·보상 화면 등에서 게임 흐름을 막지 않는지, `map_route` 선 위치.
- 게임 툴팁 시스템(`NHoverTipSet`)을 직접 쓸 수 있는지(지금은 직접 그림).

## 단계

### 0. 바탕 (진행 중)

- 사용자 설정 차단: `ANTHROPIC_*`·`CLAUDE_*`·`MCP_*` 환경변수 제거, CLAUDE.md 탐색과 자동 메모리 끄기, `--setting-sources user`, `--disable-slash-commands`. 미끼 CLAUDE.md/AGENTS.md로 차단을 확인했다(2026-11-19).
- Sonnet medium 고정, MCP 연결을 기다린 뒤 첫 턴 시작.
- 남은 일: 실제 게임에서 확인, 회귀 확인용 외부 도구 점검 스크립트(외부 채팅 방식의 호출을 한 번씩 돌려 결과를 비교).

### 1. 관제 세션과 플레이 세션 (핵심)

- 메인 메뉴에서는 관제 세션, 런 안에서는 플레이 세션과 대화한다. 모드가 런 시작과 끝을 감지해 채팅 상대를 바꾼다.
- 관제 세션: 세션 ID를 파일에 보관해 게임을 다시 켜도 이어진다. 런 고르기와 시작, 지난 런 돌아보기, 런 사이의 학습 메모를 맡는다.
- 플레이 세션: 런마다 새로 연다. 저장된 런을 이어 하면 그 런의 세션을 이어 쓴다(런 시드와 시작 시각으로 구분). 런이 끝나면 닫는다.
- 프롬프트 조립: 조각(공통 도구 사용법, 역할, 플레이 단계, 게임 안 UX, 사용자 선호, 학습 메모)을 역할에 맞게 합친다. 기본값은 저장소의 `prompts/`, 사용자가 고친 사본은 게임 전용 폴더에 둔다. 프롬프트 버전을 세션과 함께 보관해, 재개할 때 바뀐 내용을 알린다.
- 인수인계: 관제 → 플레이 "런 브리핑"(단계, 목표, 관련 메모), 플레이 → 관제 "런 보고"(결과, 교훈).
- 플레이 단계 선택은 이 단계에서 넣는다(처음에는 코플레이 Low 하나로 시작해도 된다).

### 2. 게임 안 채팅 전용 통로

- 3·5·6단계가 필요로 하는 바탕이다. 게임 안 세션에만 보이는 도구나 표기를 둘 곳을 만든다(별도 MCP 경로 또는 세션별 도구 목록). 외부 채팅의 도구 목록과 동작은 그대로 둔다.

### 3. 선택지 버튼

- 에이전트가 선택지를 물을 때(특히 플레이 중) 채팅창에 버튼으로 보여 준다. 누르면 그 내용이 사용자 메시지로 들어간다.
- 방식(2026-11-19 정함): 에이전트가 백틱으로 감싼 글이 말풍선 안 그 자리에서 누를 수 있는 칸이 된다(`Markup`, 말풍선의 `[url]` 링크). 누르면 그 글이 입력창에 들어가고, 플레이어가 고쳐서 보낼 수 있다(바로 보내지 않는다).
- 백틱 안의 카드·유물 id(전투 id `c3`, 게임 id `BASH`, 강화 `BASH+`)는 이름으로 바뀌고, 마우스를 올리면 툴팁이 뜬다. 예: `` `c3 → c5 → c7 → c9` ``가 [발놀림+ → 탈출구 → 생존자 → 정밀 사격]으로 보인다. 같은 이름의 카드가 여러 장이어도 id로 정확히 가리킨다. 입력창에는 이름이 들어간다.
- 결정이 여럿이면 결정마다 칸을 따로 준다(예: 계획 칸 + 포션 칸). 메시지는 받은 그때 한 번 만들어 두므로, 전투가 끝나 전투 id가 사라진 뒤 대화 기록을 다시 그려도 이름이 유지된다.
- 처음에는 답 끝의 `[[선택: a | b]]`를 버튼 줄로 바꾸고 누르면 바로 보내는 방식이었다. 질문이 둘일 때 한쪽만 보내지는 문제와, "A"만으로는 무엇에 대한 답인지 약한 문제 때문에 바꿨다.
- 외부 채팅에는 영향이 없다.

### 4. 화면 정보를 플레이어와 같게

- 화면에 보이는 정보는 모두 도구로 조회할 수 있게 한다. 화면별로 스크린샷과 `state`/`info` 결과를 나란히 놓고 빠진 정보를 찾는다(툴팁, 적 파워, 업그레이드 미리보기, 지도 노드 정보, 이벤트 본문 등).
- 외부 채팅에도 이득이므로 기존 도구를 넓히는 방향으로 한다(동작을 바꾸지 않고 정보만 더한다).

### 5. 플레이어 행동 기록 첨부

- 마지막 메시지 이후 플레이어가 한 행동(카드 사용, 선택, 이동)과 정보 조회(덱 보기, 지도 열기, 카드 살펴보기)를 다음 메시지 앞에 붙인다.
- 행동은 기존 이벤트 기록(`EventLog`)을 쓰고, 정보 조회는 화면 열기를 새로 감지한다.

### 6. 중요한 판단 뒤 자동 반응

- 턴 종료, 카드 보상 선택, 경로 선택, 이벤트 선택, 전투 끝 같은 시점에 모드가 세션에 알림을 보내 에이전트가 먼저 반응한다(사용자 메시지로는 보이지 않게).
- 플레이 단계에 따라 켜고 끄며, 너무 자주 부르지 않게 간격과 조건을 둔다. 5단계의 행동 기록을 함께 넘긴다.

### 7. 설명할 때 보여 주기

게임 안 전용 도구로 둔다(2단계 통로). 게임 상태는 바꾸지 않고 보기만 한다.

- 게임 화면 열기: 에이전트가 설명하면서 덱 목록, 더미, 카드 상세를 게임 화면에 연다.
- 지도: 채팅창에 지도 그림을 띄우지 않는다. 게임의 실제 지도를 열고, 제안하는 경로를 그 지도 위에 직접 그린다(`render_map` 그림은 외부 채팅용으로 남긴다).
- 카드·유물: 채팅창 말풍선 안에 게임의 카드·유물 모습으로 띄운다. 마우스를 올리면 게임과 같은 툴팁(키워드 설명 등)이 뜬다.

## 나중에

- 모델과 effort 선택(관제·플레이 따로), Codex 지원.
- 답 실시간 표시(`--include-partial-messages`).
- 제안한 카드를 게임 화면(손패, 보상 화면)에서 강조하기.
- 채팅창 접기/펴기, 게임 화면을 클릭하면 입력창 포커스 놓기.
