# 게임 안 채팅창 (설계 메모)

상태: 검토 단계. 구현 전이다. 기준 게임 버전 v0.111.1.

목표: 게임 화면 왼쪽에 에이전트와 대화하는 채팅창을 두고, 게임 화면은 오른쪽으로 옮겨 서로 가리지 않게 한다. 채팅창 뒤에서는 모드가 Claude Code를 직접 실행하고, Claude Code는 이 모드의 MCP 도구로 게임을 본다.

## 1. 모드로 할 수 있는 것

게임 코드에서 확인한 내용이다.

- 모드 DLL은 게임과 같은 프로세스에서 실행된다. Godot 장면 트리 전체에 접근할 수 있으므로 패널, 버튼, 글자, 이미지 같은 UI 노드를 코드로 만들어 화면에 둘 수 있다. 이미지 도구가 이미 이 방식으로 화면 밖 SubViewport에 노드를 만들어 그린다.
- 기존 화면(전투, 지도, 상점 등)의 노드를 찾아 버튼을 추가하거나 단축키 입력을 받을 수 있다.
- 모드 로더가 Harmony를 지원한다(`ModManager`). 화면이 열리는 시점에 UI를 붙이거나 게임 함수의 동작을 바꿀 수 있다.
- 모드 설정의 `has_pck`로 리소스 팩(`<모드 id>.pck`)을 함께 배포할 수 있다. Godot 에디터로 만든 장면, 이미지, 폰트, 셰이더를 쓸 수 있다. 게임의 카드 그림, 아이콘, 폰트도 그대로 쓸 수 있다.

제약:
- MCP는 에이전트가 요청하고 모드가 답하는 방식이라, 모드가 먼저 에이전트를 부를 수 없다. 채팅창 구조에서는 모드가 Claude Code 프로세스의 입력을 직접 쥐고 있으므로 이 제약이 해소된다(3절).
- 기존 화면의 노드 구조에 기대는 UI는 게임 업데이트로 깨질 수 있다. 지금처럼 기능별로 `Features`로 격리해서, 깨지면 그 기능만 꺼지게 한다.
- Harmony 패치가 있으면 게임이 오류 보고와 피드백에 "모드 사용"으로 표시한다(`SentryService`, `NSendFeedbackScreen`). 이미 모드를 쓰고 있으므로 달라지는 것은 없다.
- 게임 규칙을 바꾸는 패치는 멀티플레이 동기화와 업적에 영향을 줄 수 있다. 이 모드는 싱글플레이 전용이므로 크게 문제 되지 않는다.

## 2. 화면 배치: 채팅창 자리 만들기

게임은 화면 비율 설정을 지원한다(`NGame`: 자동, 4:3, 16:10, 16:9, 21:9). 고정 비율이면 `ContentScaleAspect = Keep`과 비율별 `ContentScaleSize`(16:9는 1920×1080, 21:9는 2580×1080)를 쓴다. 전투방은 화면 폭에 맞춰 캐릭터 크기와 위치를 다시 계산한다(`NCombatRoom.AdjustCreatureScaleForAspectRatio`: 가장 오른쪽 캐릭터가 폭을 넘으면 아군과 적 컨테이너를 같은 비율로 줄이고 적을 왼쪽으로 당긴다).

### A. 게임 화면 전체를 오른쪽으로 축소 (우선 실험)
- 루트 뷰포트의 그리기 변환(canvas transform)으로 게임 화면 전체를 오른쪽 70~75% 영역에 축소해 그리고, 남은 왼쪽 띠에 채팅창을 둔다.
- 장점: 전투, 지도, 상점, 이벤트를 한 번에 해결한다. 화면별 수정이 필요 없다.
- 확인할 것:
  - 별도 CanvasLayer에 그려지는 UI(상단 바, 툴팁, 팝업 등)가 같이 움직이는가. 안 움직이면 레이어별로 같은 변환을 걸어야 한다.
  - 마우스 입력 좌표가 축소된 화면에 맞게 변환되는가.
  - 화면 비율 설정과 전체 화면 전환 때 변환을 다시 걸어야 하는가(`NGame`의 창 크기 변경 신호).

### B. 채팅창은 겹치고, 화면별로 배치만 조정
- `AdjustCreatureScaleForAspectRatio`에 Harmony로 끼어들어, 쓸 수 있는 폭을 채팅창만큼 줄여 계산하게 한다. 게임이 캐릭터를 오른쪽으로 옮기고 필요하면 줄인다.
- 단점: 왼쪽 아래 UI(에너지, 뽑을 카드 더미 버튼, 손패 왼쪽 끝)는 따로 옮겨야 한다. 지도, 상점 등 화면마다 손봐야 하고, 업데이트에 약하다.

### C. 접었다 펴는 패널
- 반투명 패널을 단축키로 열고 닫는다. 가장 쉽지만 열어 둔 동안 게임 화면을 가린다.

순서: A를 짧게 실험한다. 막히면 B와 C를 섞는다.

## 3. 에이전트 연결

다른 프로젝트(TypeHelp: 게임 앱이 플레이어 PC의 Claude Code를 동반자로 실행하는 구조)의 로컬 에이전트 연결 방식을 따른다. TypeHelp에서는 Claude Code가 stdio 도구 서버를 거쳐 게임 앱에 HTTP로 도달한다. 이 모드는 게임 안에서 HTTP MCP를 이미 제공하므로 그 중간 단계가 필요 없다.

```
[게임 안 채팅창] ⇄ (모드 내부: 메시지 큐, 이벤트 해석) ⇄ claude -p (stream-json 양방향)
                                                          │ MCP http: 127.0.0.1:15527/mcp (기존 서버)
                                                          └─▶ state / act / info / search / ...
```

### 실행
- 모드가 `claude -p --input-format stream-json --output-format stream-json --verbose`를 자식 프로세스로 띄운다.
- `--mcp-config`로 기존 엔드포인트와 토큰을 넘기고 `--strict-mcp-config`로 다른 MCP 서버를 막는다.
- 내장 도구는 끄고(`--tools ''`) 게임 도구만 허용한다(`--allowedTools mcp__sts2__*`). 권한 질문은 모두 거부한다.
- 작업 폴더는 비어 있는 전용 폴더를 쓴다. Claude Code는 대화를 작업 폴더 기준으로 저장하고, `--resume`도 같은 폴더에서 찾기 때문이다. 폴더 이름과 위치를 바꾸면 이전 대화를 이어 갈 수 없다.
- 시스템 프롬프트는 파일로 넘긴다(`--system-prompt-file`). 함께 플레이할 때의 규칙(전투 시작 설명, 행동 전 확인, 짧은 설명)을 담는다.
- 환경변수 정리: API 키 등 구독 로그인 외의 과금 경로와, 게임을 실행한 Claude Code 세션의 흔적(`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID` 등)을 지운다.

### 메시지와 이벤트
- 프로세스 하나에 대화 하나. 채팅창 입력은 큐에 넣고 한 번에 한 턴씩 stdin에 쓴다.
- 첫 전송은 MCP 연결을 기다린 뒤 보낸다(Claude Code 버전에 따라 대기 시간 또는 `CLAUDE_CODE_MCP_STARTUP_WAIT_MS`).
- stdout은 UTF-8 줄 단위 JSON으로 읽는다. 처리할 이벤트:
  - `system/init`: 모델, MCP 연결 상태, 세션 ID
  - `assistant`: 글은 채팅창에, 도구 호출은 짧은 표시(예: "카드 사용 중")로
  - `result`: 턴 종료, 오류 표시, 다음 큐 전송
  - `system/compact_boundary`: 압축 표시. 다음 메시지 앞에 기억을 다시 넣는다
- 로그인 만료 등 오류는 채팅창에 안내한다.

### 세션
- 런 하나에 대화 하나(런 시드로 구분). 세션 ID를 모드 설정 폴더에 보관하고, 이어하기에서 `--resume`으로 재개한다.
- 재개에 실패하면 새 대화로 시작하고, 현재 상태(`state`)를 첫 메시지로 넣는다.
- 시스템 프롬프트가 바뀌면 `--resume`은 이전 프롬프트를 유지하므로, 바뀐 내용을 메시지로 알린다(프롬프트 버전을 세션과 함께 보관).

### 게임 안이라서 좋아지는 점
- 지도 그리기와 카드 이미지를 파일로 보낼 필요 없이 채팅창에 바로 띄운다.
- 에이전트가 제안한 카드나 경로를 게임 화면에서 바로 강조할 수 있다.
- 상황 물어보기 버튼처럼, 게임 쪽에서 대화를 시작할 수 있다.

## 4. 정할 것
1. 화면 방식: A 실험부터 할지, 처음부터 C로 단순하게 갈지.
2. 계정: 이 PC의 평소 Claude Code 로그인을 그대로 쓸지(개인용), 게임 전용 설정 폴더(`CLAUDE_CONFIG_DIR`)로 분리할지(배포용).
3. 대화 위치: 게임 안에서만 대화할지, 외부 채팅(에스텔)과도 이어지게 할지. 후자는 외부 채팅에 메시지를 넣고 받는 방법부터 확인해야 한다.

## 5. 첫 단계
1. 화면 축소 실험(A): 루트 그리기 변환으로 게임을 오른쪽에 줄여 그리고, 전투, 지도, 상점, 툴팁, 클릭이 맞는지 스크린샷으로 확인한다.
2. 빈 채팅 패널: 왼쪽 띠에 입력창과 메시지 목록만 둔다(에이전트 없이 메아리).
3. Claude Code 연결: 3절의 실행과 이벤트 처리. 세션 보관과 재개.
4. 채팅창에 이미지 표시, 화면 강조 연동.
